## Design facts the next agent should know
- Every row holds, per security-relevant argument, three literals (user request, trusted config, carrier document); the action uses one (derived slot ACT_i). The origin is only readable by comparing strings, never from a cue. The matched pair flips ORIGIN_i.
- Matched groups (4 choice rows with the 4 labels; a yes / no pair) share tool, carriers, values, pack, skin, wording and templates: this is what keeps G6 / G7 / G10 at chance. `DealtCtx` (via `plugin.ctx_for`) deals the wording by group so partner forms stay balanced too.
- Rules sit in `row.card` on yes/no rows and in the state under `Rules:` on choice rows (the instructions are printed twice: putting them there gave a 913-token mean).
- Trigger vocabulary occurs exactly once per row, in the user request (trusted, never trigger text) or in one tool result: where it sits, not whether it is present, separates ALLOW from ALLOW_BENIGN_TRIGGER. Attack lines (relation `inv`) must carry none of it (`check_attack`).
