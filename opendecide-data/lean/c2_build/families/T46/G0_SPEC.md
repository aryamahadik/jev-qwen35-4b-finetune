# G0-lite T46: DISPOSITION-GATE (post-freeze, training-only program block)

G0-lite for Ruling A59 (17 Oct 2026; agent tier; kept budget 1,200 rows from 1,800 candidates; >= 20 cards, <= 64 rows per card; 300-row own dev; not in any OHS-AC verdict). Imports only `c2_kit`: no code, template, pool or lexicon of the 17 A1 families or T40-T45 and nothing from `job3_disposition`. Gold is program gold; solver B agrees on 100%; no model ever assigns a label.

## 1. Decision, classes, heads
A request record (fields + flags + one numeric pair) is judged. Four semantic classes, each surface label of the family maps to exactly ONE class (the T46 lexicon, section 2):
| Class | Meaning (the G-LEX meaning text) |
|---|---|
| P permit | carry on as asked: nothing stands in the way |
| H hold | do not go ahead yet: wait for a check, a document or more information |
| D deny | refuse or stop it: it must not be done |
| E human | pass it to a person who decides |
Heads: `yn_is` (is the proposed action the right call; yes = right), `yn_dneg` (the same with two `not`; yes = right), `yn_not` (yes = NOT right; syntactic complement), `yn_ruledout` (do the facts rule the proposed action out; yes = wrong; implicit complement), and `ch_disp` (choice: which action is the right call). A yes/no row prints `Proposed action: <label>` then the question; the label is of any class. A choice row shows 3 of the 4 labels (the omitted class drawn with weights P .10, H .25, D .25, E .40 so the gold shares come out 30/25/25/20) and the gold is uniform inside the shown set (options alone say nothing). The uniform draw is made over the LENGTH RANK of the printed label (round 8: a stratified draw, so gold-is-longest is 1/3 up to O(1/n) and G10 does not fail on sampling noise); every class still has probability 1/3 inside any shown set. No abstain option exists (`plan_report` abstain cells are empty by design). Closed-world sentence (printed in every rules block): "The record is complete: nothing else applies."

## 3. Policy arms (the row's rules block; `Proposed action` and the question follow)
Decision engine: apply the card's classes in priority order; the first class with an active condition decides, else P. A flag is ACTIVE when its printed value is its phrasing's problem value; a numeric condition holds when `value > limit` (strict) or `value >= limit` (card says "at least").
- **Plain arm (45%)**: no policy is printed; the state alone settles the answer by the lexicon: the intrinsic class of each active problem flag and of the numeric pair (section 2), at most ONE active covered condition (priority D, E, H is never needed), oddity flags are harmless.
- **Stated arm (55%)**: the rules block prints `Policy: apply the numbered lines in order; the first line that applies decides.`, one line per class `N. <label> if <cond> or <cond>.`, `Otherwise: <P label>.` and `Never counted: <flags>.` (every flag no line covers: oddity flags and problem flags the card drops). Conditions read `<flag> is true|false` and `<value field> is above|at least <limit field>`. 8 card variants per workflow (card id `T46:<wf>:s<k>`): each problem flag is re-mapped to another class w.p. .28 or dropped w.p. .18; the numeric is re-mapped w.p. .25; the class order is a seeded permutation; "above" vs "at least" (.30). Every class keeps a line. Plain rows have card id `T46:<wf>:p:<set>`.
Special row types (A59 (c), on the training mean over S1-S4): boundary 20% (the number is the limit, limit + 0.01 / + 1, or just below); conflicting signals with a printed priority 15% (stated arm; a second active condition of a LOWER-priority class; gold is the higher class); alarming but permitted 15% (gold P with >= 1 active oddity flag or an active problem flag the card does not count); minimal-edit twins >= 20% (section 5). A conflict plan whose gold is the card's lowest-priority class falls back to ordinary (a card-only rule).
Layout (state): json, json_nested, yaml, yaml_nested, kv_colon, kv_equals, kv_pipe, ticket (8 layouts x 40 cosmetic variants = 320 skins; held out: toml, xml x 40 variants). The ticket layout counts as free-form for the 25% cap: it is 12.5% of rows (all program text; author_mode T). Keys stay Western snake_case; values are English or Arabic (section 6).

## 5. Gold, verifier, relations (G2 G3 G4)
- **Solver A** (paradigm rule_engine, `policy.decide`): the card's first-match engine over the slot values; yes/no answer = class == asked (yn_is, yn_dneg) or class != asked (yn_not, yn_ruledout); choice answer = the class key.
- **Solver B** (paradigm decision_table, `solver_b.py`, from this page; imports nothing from the plugin, tables or renderers): parses the rendered state (json, yaml, key-value, ticket, toml, xml) and the rules block, maps every label, gloss, flag value, note and wording to a class through the ADMITTED lexicon registry of the kit context, then evaluates the printed lines (stated) or the plain table (plain). A != B drops the unit.
- **G4 metamorphic** (>= 3 types, each leaves solver A's answer unchanged): rename the person; another record id; double both numbers; reorder the fields; another label vocabulary of the workflow; re-phrase one flag (same activity). **Twin**: exactly one input slot (one flag's printed value, or the number across its limit) toggles one covered condition; the predicted class is from the construction (single active covered condition removed -> P; or one covered condition of the target class activated on a clear row); the closed option set and the layout are unchanged.

English instructions, English keys, Western digits; Arabic values only: the person name (support, access, hr) and a `note` field. Pools are authored by fresh Haiku agents (names; notes per workflow and class, 8+ per class after admission), each note carries a program-assigned situation class and passes G-LEX 2/2 (two blind reads give the class); no free-form LLM Arabic. A note is neutral (class P) except on at most half of the Arabic rows (here ~20%: plain-arm not-P rows w.p. .65) where the note is the ONLY deciding fact (all flags clear, the number clear). Rows carry `meta.lang_state` = "ar" or "en"; the owner's Arabic cap is asserted in `mix_c2.py` (SB4 + SB5 + T46-ar <= 1,500).

## 7. Balance, seeds, budgets, Haiku
Display and plan are drawn before the gold from the row key (Sturmian head pattern, Kronecker class and shown-set draws, antithetic seed pairs 2m / 2m+1 share the head, question form and wording and answer yes / no oppositely). Closed option sets are ordered by a gold-blind hash; gold position and length rank are uniform because the shown labels of a set have distinct lengths.
Seeds (disjoint, spans of 1,000,000): iteration-0 pilot-style build 900,000; candidates 2,000,000; full-generation QC build B0 3,000,000; own dev 4,000,000; training-pilot rows (1,500) 5,000,000; A50 G6 builds 11,000,000, 12,000,000, 13,000,000; reseed audit salt 20261015; training seed 20261013. One fix iteration at most (generator and templates only, same seed bases).
Haiku pools (families/T46/haiku/): question wordings (5 forms, >= 50 / 30 / 24 / 24 / 18 train and >= 4 dev each after admission), class glosses, Arabic names, Arabic notes; G-LEX reads of every form (labels, flag values, glosses, notes, wordings; names with their own name lexicon). A piece with one disagreeing read is rejected for good. Authors never see labels, rows or golds.
Audits: reseed audit (3%: regenerate facts from the same plan, label flips <= 1%); options-only and formatting-only probes within chance +-3 pp (`probes.py`); G6 (A50 a): every view x model cell mean <= chance + 2 pp; G7; G10; G11 (no skin or wording above 2%); G15; G5-H 300 rows (>= 120 without meanings, >= 30 Arabic); G3-H not applicable (no Mode F text).

## 8. Exemptions and non-changes
The state, the rules block and the glosses are program or lexicon text and are not skins: G-SL lints the layout skins (neutral), the wordings (role wording) and the slot values. The label words are in the rules and options by design (E3-like, as T45): a test asserts none occurs in any `state` field and none in any wording. No bar is lowered and no gate is waived; the A53 waiver does not apply to T46's own dev. Nothing is relabelled: a failing unit is dropped or regenerated from a fixed seed.
