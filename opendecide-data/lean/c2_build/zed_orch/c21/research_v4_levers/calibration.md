# C2.1 levers, angle "calibration and abstention" (web research, 18 Oct 2026)

Scope: levers NOT already in PLAN_TRAINING_SIDE.md v3.1. Already in the plan and therefore not repeated: per-type temperature (leave-one-group-out, bounded [0.8, 1.3]), plain CE with no label smoothing, ECE/Brier/trap-slice ECE reporting, ECE <= 3.5% gate, checkpoint/alpha blending, trap selection, ALLOW/ASK/BLOCK classes in the permission families, a 3-point ASK band with a coverage-vs-error curve, FP8-KL training with a 99.5% argmax parity bar, PriDe offset. Think tier, FP8 serving and block-FP8 are dropped/failed and not re-planned.

Tags: author-run = the paper's authors ran it; independent = a third party ran it; vendor = the seller's own docs/claims. "DERIVED" = my arithmetic or judgement from the cited numbers, not a measurement on our model. "UNVERIFIED" = seen only in a search summary, or the primary page could not be read.

Reading rules I applied: no model was run and nothing was downloaded. Several PDFs could not be decoded by the fetch tool, so numbers from those come from search summaries and are marked.

## Four findings that matter before the table

1. Under an independent protocol, Jev is already well calibrated on typed decisions. Rafe and Das (arXiv 2610.00346, 29 Sep 2026, independent; top-label ECE, 10 equal-mass bins, 5-fold cross-fitted temperature) measured hosted Jev 1.13 at ECE 0.033 (D1 typed decisions) and 0.032 (D2 CLINC-150). Our plan gate "ECE <= 3.5%" would NOT beat that. Jev's weak spot in the same paper is pooled social-science tasks: shipped ECE 0.251, which one fitted temperature cuts to 0.038. So "beats Jev on calibration" is credible on unseen task types and not on in-distribution typed decisions, unless we reach roughly 2.5% or lower under the same protocol. Our own "Jev 6.0" figure uses a different protocol and should not be the headline. (Lever C3.)
2. Temperature scaling fixes the size of confidence, not the ordering. Safety-Flag (arXiv 2609.19072, Aug-Sep 2026, author-run) reports one fitted temperature cuts ECE 2.8-6.0x on six LLMs "without changing predicted labels or the confidence ordering". So coverage-vs-error (abstention quality) only improves through training-side or ranking-side levers (C6, C8, C9, C10), not through more post-hoc scaling.
3. Jev's documented confidence API has gaps we can fill. Docs/third-party summaries: Choice returns per-option probabilities plus one `confidence` number; yes/no ("Noul") returns only P(yes) with no confidence field; no abstain/none option is documented; no formula is published; a code example where reading a missing `confidence` silently never fires a gate is called out as a gotcha (OpenRouter Jev docs, vendor, read 18 Oct 2026; flaviocopes.com/jev-confidence.md, third-party summary of vendor docs). (Lever C15.)
4. Real traffic has a different base rate from training. Our balance rule is 40-60% yes per family. If a customer's true block rate is 10%, a source-calibrated model is off by a logit shift of ln(0.111) = -2.2 (DERIVED: odds ratio (0.1/0.9)/(0.5/0.5)); 5% gives -2.9. That is far larger than any ECE gain from loss tweaks. (Lever C13.)

Do now, cost near zero, no rule friction: C3 (protocol and honest target), C2, C10, C14, C16, C8. These protect the calibration claim and the ECE gate; none needs new training.
