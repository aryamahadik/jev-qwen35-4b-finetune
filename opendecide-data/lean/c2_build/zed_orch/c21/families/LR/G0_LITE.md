## 1. Decision and scope

- Block R = public TRAIN splits mapped to C2's rendered layout with each dataset's OWN human or program labels, feeding mainly the GENERAL score (intent, evidence, abstain, commonsense, reading, tables, norms) and the P1 realism slices. No third-party LLM writes or labels any block-R row (rule 3, wording of v3.2-r Sk 6). The only Claude-authored block-R text is (a) the benign twins of the Aya and Gandalf-summarization rows (written by L-I under the program-enforced literal ban; their gold is benign by construction) and (b) the question-STEM wording pools, which carry no data and no label (flagged OQ-R1).
- English only, no vision (A82 9). No social-platform posts and no contest or exam statements inside a set (A82 4). No When2Call train, WildGuardMix or WildJailbreak (A82 5).
- Size: the per-dataset caps of section 5 sum to 22,100 non-code block-R rows plus MBPP 300 (LR-12) = 22,400, plus up to 3,000 tasksource rows = 25,400 (DERIVED, my arithmetic on the plan table; the plan's "about 24,600" is also DERIVED). The REAL size is measured: B2 sets enter only under the strict whole-split reading and every dataset needs its own PASS. Code-realism rows (9 datasets, 5,700 at the caps; plan: about 5,000) count inside their P1 families; MBPP (LR-12) is a P1-realism slice with family id LR-code, counted in block R and outside T42c's 3,000 [Opus b1 LR-M7]. The Aya and Gandalf twins (about 400) are extra block-R rows (OQ-R2; 25,800 with them). The mix cap (125,000) and the money shed order (plan 16.7: caps lowered uniformly, floor 300, no dataset removed) are the only size controls; nothing is cut from an estimate.
- Label meaning: a block-R row asks the dataset's own question as a pick-one Choice or a yes/no; the gold is the dataset's own label (or the label of the gold object) passed through an Opus-approved recast table.
- Output to the product: none (general skill and robustness data, trained with the option-letter loss like every other row). Block R is also protective: it keeps G from regressing.

## 4. Mapper template (every dataset)

STEPS (order fixed): 0 record (E1-E10) -> 1 train-only reader -> 2 recast table (Opus) -> 3 mapper -> 4 stamp wrapper (plan 16.1 step 2) -> 5 A46 drop-only screen -> 6 set-level report (once per dataset) -> 7 manifest flags.
1. TRAIN-ONLY READER (CPU test, 100%): reads only the train split; where one file holds several splits a STREAMING reader filters on the split field, and a CPU test asserts that no test/dev id reaches the output. Where a release has no split, a seeded program freezes a 10% hold-out (by project, repo, CWE family, causal graph or the unit the release naturally groups) BEFORE mapping; it is an internal held-out target (registered for G13) and is never trained.
2. RECAST TABLE (Opus approves in ONE batch per source group): fields = dataset id and release; train file and split field; source label set; recast option set; target format (Choice k, or yes/no); distractor policy; declared balancing; declared drops; question-form ids; span-selection rule (long documents); expected token mean; table sha. The label of a mapped row is the dataset's own label through this table. CHECK (per row, in the stamp wrapper): the mapper recomputes the gold from the source row and the table with an independent function; mismatch = row dropped (100% agreement is the bar).
3. ROW FORMAT (rule 4): C2's rendered layout (cygnet + schema_branch_mark; or the read-twice layout only if the Sat 24 program check passes, Sk 16); pick-one or yes/no; options shuffled; the 20% random non-identity permutation copies are made at MIX level, not here. Large label sets show the gold plus k-1 program-chosen hard distractors with k in {4, 8} rotating (each k 45-55% of such a dataset's rows); the distractor chooser is a CPU program (label-name token overlap plus the confusion of a TF-IDF logistic regression fitted on the dataset's own TRAIN split only; it chooses distractors and never writes a label). Multi-label sets become one yes/no per option. Ordinal sets become an ordinal-bucket Choice, only after the C2 renderer's Score support is checked. Long documents use PROGRAM SPAN SELECTION: the gold-bearing span plus distractor spans; never a cut that drops evidence; length drops are logged. No gold-removal "none of these" rows are built (a generic NOTA option is built but OUT of the mix, A82 default for O10); dataset-native abstain labels (out of scope, unanswerable, not enough info, unknown, not mentioned) stay and are never reduced.
4. TOKEN RULE (G6): mean <= 800 per dataset; no row above 1,536; rows above 1,024 tokens on <= 10% of the dataset.
5. NAMES: L-R and P1-realism rows carry REAL tool, language, runner, package and entity names, so the seeded-namespace rule and the row-start names guard do not apply to them (scoped exemption written into the guard by the row family field with a CPU test). A program extracts the vocabulary of every L-R and P1-realism source into the names-only manifest v1.1 (v1.2 for Fri 23 additions) BEFORE the OHS-5 freeze, so the sealed side keeps C-transfer clear of those names. Every other row keeps the closed allow-list.
6. LENGTH COVERAGE (A21): a CPU histogram of block-R token lengths vs the public-G panel and the G-like dev lengths; if a gap shows, the mapper prefers longer eligible examples inside the 1,536 cap (a selection rule, never a relabel).
