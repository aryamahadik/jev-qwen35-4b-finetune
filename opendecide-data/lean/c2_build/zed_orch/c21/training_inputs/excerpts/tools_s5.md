T55 RECOVER-ESCALATE
8. Add an AMBIGUOUS-WRITE class (timeout, 5xx or lost acknowledgement on a non-idempotent write). Options: retry same call with the same idempotency key / read back state first / retry as new / ask / stop. Gold is a ledger simulation: the program knows whether the write committed, whether a read path exists, and whether an idempotency key was offered. Rule of the generator: key offered means retry with the same key; read path exists means read back first; neither means escalate. Evidence: LIMBO shows frontier models duplicate in 56-74% of cases when read-back cannot reveal the outcome, keys cut duplicates 28% to 4%, and agents over-report success 90% of the time after a duplicate. We build our own ledger; no LIMBO code was found. https://arxiv.org/abs/2609.29095
9. Add the IMPLICIT-ERROR class: the result is well-formed but violates an invariant (empty list when a count was stated; negative quantity; id not in the earlier list). Gold: invariant checker. Evidence: implicit errors cost 37.15 recovery points on average vs explicit (ToolMaze); receipts naming a violated property plus recovery tools lifted ToolMaze completion 10.9% to 28.1% (Outcome Monitors); detection beyond the mined vocabulary was only 46%, so generate violation types the model is NOT told about in the card. https://arxiv.org/html/2606.05806v1 , https://arxiv.org/abs/2608.19303
10. Add paired negatives for "blind retry": same error text, but one row where the message names the bad argument (fix it) and one where it does not (switch or ask). Small models repeat the same invalid call after an error (Fission-GRPO premise). https://arxiv.org/abs/2601.15625
11. Loop vs polling: keep the state-change predicate. There is no public eval for it, so report it only on OHS-5, labelled "our items". Identical (tool, arguments) is a weak signal alone.

T56 DONE-CLAIM
12. Matched pairs must hold the claim text identical across true and false rows, and the true/false difference must live only in tool outputs. Add a SHORTCUT GATE: train a TF-IDF + logistic regression on the claim text alone; if it scores within a set margin of our model on the family's validation split, the family has a text shortcut and fails G5-H review. Evidence: judges reading the closing message cap at AUROC 0.65 because confident language appears in false-success runs too, while a TF-IDF model on trajectories reaches 0.83-0.95, so text cues are strong enough to be exploited either way. https://arxiv.org/html/2606.09863
   [REFUTER EDIT 18 Oct 2026: KEPT as a gate, evidence corrected. (1) The paper says judges "anchor on confident closing-message language as evidence of completion"; it implies but never states a direct comparison of closing-language frequency between true and false runs. (2) 0.83 and 0.95 are TF-IDF+XGBoost; TF-IDF+LR is 0.849 (tau2) and 0.915 (AppWorld). (3) The AppWorld figure uses API-call-sequence tokens, so it is not evidence of a CLAIM-TEXT shortcut; only the tau2 figure (trajectory or closing-message features) is. (4) In natural runs the closing message differs between classes, so the paper does not show that a claim-only classifier would beat chance on our matched pairs where claim text is identical by construction. The gate is therefore a sanity check on our generator (it should score near 0.5 by construction), not a replicated finding.]

Program-gold generation recipe (item 20, for the T54-T56 G0-lite specs)
20. Program-gold generation recipe to write into the T54-T56 G0-lite specs (no other LLM needed): (i) Claude-authored scenario templates; (ii) code builds a tool DAG and a simulated state/ledger; (iii) a perturbation manifest on a 2x2 (explicit/implicit x transient/permanent) plus the ambiguous-write class; (iv) gold from DAG levels, invariant checkers and ledger comparison; (v) Haiku only rewords prompts. Sources of the method: ToolMaze (DAG enumeration and fixed perturbation schedule), CAR-bench (trajectories sampled from a programmatic API graph), LIMBO (ledger grading). All three use an LLM somewhere (query writing or user simulation), so we copy only the program parts.
