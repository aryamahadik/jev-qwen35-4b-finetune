C4. MCP-Atlas "next-tool per step" framing (Tier 2). The paper grades by claim coverage on the final answer precisely "so alternative valid tool-call paths can earn credit" (https://arxiv.org/abs/2602.00933). A single gold "next tool" from the stored TRAJECTORY will mark valid alternatives wrong. Fix: score only steps whose tool is uniquely forced by data flow (the next call consumes an output of the previous one that no other tool can produce), or score "tool in the set of tools in the reference trajectory". Say so in the protocol line. The public split is 500 rows, CC-BY-4.0 on Hugging Face, fields ENABLED_TOOLS (10-25 tools per task), PROMPT, GTFA_CLAIMS, TRAJECTORY (https://huggingface.co/datasets/ScaleAI/MCP-Atlas). The plan's "5-20 distractors" for T54 is below the 10-25 that MCP-Atlas shows per task; widen to 25.
   [REFUTER EDIT 18 Oct 2026: PARTLY REFUTED. (a) The HF card says ENABLED_TOOLS is "A controlled subset of 10-25 tools exposed to the agent per task", but the paper (https://arxiv.org/html/2602.00933, section 3.2 and intro, [author]) says "6-37 tools (mean 15.2), of which only 2-8 are required (mean 4.1)" and "remaining tools (mean 11.1 per task) are distractors". The two sources disagree; the paper does not say whether its range is the public split. (b) 10-25 counts ALL enabled tools (required plus distractors), but plan v2 says "5-20 DISTRACTORS". The units differ. In MCP-Atlas the mean is 11.1 distractors per task, so v2's 5-20 distractors is not "below" MCP-Atlas. "Widen to 25" is a design choice we may still make, but it is not backed by MCP-Atlas.
