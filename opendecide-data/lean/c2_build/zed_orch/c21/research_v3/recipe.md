## 1. What is new since plan v2

v2's `training_recipe` fixes: init, one stage, mix, replay 1.0x/1.5x, prompt layout, order invariance (20% reversed copies + symmetric KL, conditional), hard negatives (>=30% minimal pairs/near-misses, hard bin 2x), class weights, plain CE with no label smoothing, per-type temperature in [0.8,1.3], an 18-candidate alpha grid, snapshot stop. It does NOT state LR, epochs, warmup, LoRA alpha, dropout or target modules. Nothing below contradicts its structure; the new material is evidence for the details.

1. **LoRA hyperparameters now have a documented evidence base.**
   - LR: LoRA wants about 10x the full-fine-tune LR (fitted 9.8x), about 15x for runs under ~100 steps; optimal LR changes by under 2x between rank 4 and 512; alpha=32 used throughout; MLP layers matter, attention-only LoRA underperforms even at matched parameters. Thinking Machines, "LoRA Without Regret", 29 Sep 2025, https://thinkingmachines.ai/blog/lora/ [author-run, vendor blog, widely replicated in TRL docs https://huggingface.co/docs/trl/main/en/lora_without_regret].
   - Biderman et al. (TMLR 2024): best LoRA LRs 5e-4 (code) and 2e-4 (math) vs 5e-5 / 1e-5 full FT; recommend alpha=2r, all modules, sweep LR in [1e-5, 5e-4] and take the highest stable value; LoRA "forgets less" than full FT and than weight decay/dropout. https://arxiv.org/html/2405.09673v2 [author-run].
   - Intruder dimensions (Shuttleworth et al.): LoRA creates high-rank "intruder" singular vectors; count correlates with forgetting (rho 0.971 RoBERTa, 0.59 LLaMA2-7B); alpha=2r gave fewer intruders than alpha=8; higher LR gave more intruders and more forgetting; scaling the top intruder down (lambda 0.3-0.9) cut forgetting about 33% at about -0.1 pt accuracy; sequential LoRA over six tasks degraded faster than full FT and the authors advise against combining LoRA adapters sequentially. https://arxiv.org/html/2410.21228 [author-run].
   - Closest small-guard LoRA recipe I found: Nemotron 3.5 Content Safety (Gemma-3-4B-it): LoRA r=8 (paper Table 3) or r=16 (model card; the two disagree), alpha 32, LR 1e-4, 5 epochs, AdamW, bf16, batch 2x8 per device (GPU count not stated). Dropout 0.05, cosine and warmup 0.1 are in the paper's Table 3 ONLY (the model card does not state dropout, warmup, scheduler or batch size). The LR grid {1e-5,1e-4,5e-5,5e-6,1e-7} is on the model card only (the paper reports no grid). https://arxiv.org/html/2608.27548 and https://huggingface.co/nvidia/Nemotron-3.5-Content-Safety [vendor-run]. Note alpha 32 is 4r at r=8 (paper) and 2r at r=16 (card). Training data is partly LLM-generated/distilled (Qwen 397B/80B): recipe use only. [EDIT-REFUTER 18 Oct: split paper vs card values; verified by fetch.]
   - Unsloth's Qwen3.5-4B decision-model guide (fetched by refuter 18 Oct, https://unsloth.ai/docs/basics/train-your-own-decision-model-with-unsloth) [vendor docs]: the text says epochs 2, r=16, LR 2e-4, but the same page's code uses `learning_rate = 2e-5`, `max_steps = 240`, `lora_alpha = 16`, `lora_dropout = 0`, cosine, warmup_steps 10, batch 2x4, and `load_in_4bit = True` (which conflicts with Unsloth's own "avoid QLoRA on Qwen3.5" advice), and it trains a new classification head. The page contradicts itself on LR by 10x: treat as a starting point only, not as evidence for any value. [EDIT-REFUTER 18 Oct: was UNVERIFIED, now fetched; the 2e-4 figure is not consistent with the page's code.]
   - Qwen3.5 specifics: Unsloth says avoid QLoRA on Qwen3.5 (use bf16 LoRA), needs transformers v5, uses custom Mamba-style Triton kernels (slow first steps), default target list q,k,v,o,gate,up,down at r=16, alpha=16. https://unsloth.ai/docs/models/qwen3.5/fine-tune [vendor docs]. Whether DeltaNet in_proj/out_proj layers should be targeted: UNVERIFIED (only third-party posts). Fact checked by refuter from the model config (https://huggingface.co/Qwen/Qwen3.5-4B/raw/main/config.json, 18 Oct): hidden_size 2560, vocab_size 248,320, 32 layers, 24 linear-attention layers and 8 full-attention layers (pattern 3 linear : 1 full). So a q,k,v,o,gate,up,down target list adds attention LoRA in only 8 of 32 layers, while MLP LoRA covers all 32; this matches the TML finding that MLP matters most, and it means "same module set as C2" is the safe parity choice. 2. **Guard-model tech reports give almost no calibration or replay recipe.** I checked each:

Data is LLM-generated (Self-Instruct, Qwen-MT translation, Qwen3-32B teacher): barred for us, recipe ideas only.
   - Granite Guardian 3.0 report: SFT from instruct (instruct init beat base), Adam LR 1e-6, grad accumulation 5, up to 7 epochs, checkpoint chosen by min validation CE; verdict readout = softmax of summed exp(logprob) over yes/no-like tokens in top-20; no ECE reported. https://arxiv.org/html/2412.07724v1 [vendor-run]. Granite Guardian 3.3 and 4.1 cards state no training method and no calibration method, though 4.1 claims "calibrated yes/no judgements" (https://huggingface.co/ibm-granite/granite-guardian-4.1-8b) [vendor-run claim, UNVERIFIED].
   - Llama Guard 4: model card gives no hyperparameters in what I could reach (https://www.llama.com/docs/model-cards-and-prompt-formats/llama-guard-4/ via search summary; UNVERIFIED). Llama Guard 1: LR 2e-6, about 1 epoch (https://arxiv.org/pdf/2312.06674, search summary).

   - AgentDoG 1.0 (Qwen3-4B-Instruct-2507 etc.): NLL on the label, LR 1e-5 for all models (epochs, batch, LoRA/full not stated), over 100k synthetic trajectories, about 52% kept after QC. https://arxiv.org/html/2601.18491 [vendor-run]. AgentDoG 1.5: guard SFT LR 1e-5 then GDPO RL (G=8, LR 1e-6); agentic-safety SFT on Qwen3.5-4B batch 128, LR 5e-6, 28,705 safety trajectories mixed with 50,000 benign tool-use trajectories (about 1:1.7); the filtered-safety mix kept BFCL at 81.12 vs 78.69 for the unfiltered mix. https://arxiv.org/html/2605.29801v1 [vendor-run]. Their data uses GPT-5.4 CoT and ToolACE: barred for us.
   - OpenHands critic: 4B, full-parameter FT with BCE, multi-label (25 rubric + 1 success), MIT licence, no LR/epochs on the card. https://huggingface.co/OpenHands/openhands-critic-4b-v1.0 [vendor-run].    Net: no 2025-26 small-guard report I could read publishes ECE targets, replay ratios, or LoRA-merge procedures. v2 should not claim a "published standard" for these.

3. **Guard calibration is now a studied failure.** "Guard Models Are Overconfident Where Base Models Are Uncertain" (Sep 2026): ECE clean to adversarial: Llama-Guard-3 .013 to .308, WildGuard .004 to .196, ShieldGemma .325 to .684; at a 0.99 confidence threshold adversarial false negatives stay 11-12% (WildGuard, LG3) and 37% (ShieldGemma); base model entropy is higher on 80-93% of guard false negatives for Llama-Guard-2/3 and WildGuard (82%, 80%, 93%) but only 51% for ShieldGemma [EDIT-REFUTER 18 Oct: ShieldGemma was omitted from the range]. https://arxiv.org/html/2609.36477v1 [author-run, 5 guards, 6 attacks; the paper never states its ECE bin count, and it did not test temperature scaling or label smoothing itself]. An earlier study finds guards overconfident, temperature scaling effective, contextual calibration useful without a dev set. https://arxiv.org/abs/2410.10414 [author-run; abstract only].

4. **Label smoothing in SFT.** Gains documented on 1B-8B and 2B-7B models: LLaMA3-8B Tulu3 MMLU ECE .050 to .012 at beta 0.1, accuracy .651 to .646; Gemma2-2B .341 to .020. Benefit shrinks for smaller models with large vocab and small hidden size (authors' Remark 4.3: "cannot help"; Figure 3 shows the shrink across LLaMA3 1B/3B/8B), because smoothing only counters overconfidence. Caveat found by refuter: the same paper's Gemma2-2B (256K vocab, hidden 2304) went from ECE .341 to .020, so "gains are largest on 8B" holds for the LLaMA3 family only; Qwen3.5-4B (hidden 2560, vocab 248,320, from its config) sits in the same regime as Gemma2-2B, which is unresolved evidence, not a refutation. https://arxiv.org/html/2508.00264 [author-run]. "CogCalib" (paper title: "Towards Objective Fine-tuning: How LLMs' Prior Knowledge Causes Potential Poor Calibration?"; the name CogCalib is not on the page I read, UNVERIFIED): data aligned with the model's prior knowledge drives overconfidence; unknown data does not; Llama3-8B OBQA ECE 11.20 (vanilla SFT) to 2.50 for the paper's CoLS variant (CoECP 7.30). https://arxiv.org/html/2505.20903 [author-run, models up to 13B]. [EDIT-REFUTER 18 Oct: 2.50 belongs to one method variant, not to "the finding".]

5. **Order invariance.** Zheng et al. (ICLR 2024): selection bias is mainly token bias on option IDs, not position (removing IDs cut gpt-3.5 MMLU RStd 5.5 to 1.0 with accuracy 67.2 to 66.7; a/b/c/d gave RStd 6.8, (A)/(B) 8.1, 1/2/3/4 gave 3.8 at accuracy 65.8, which the authors call "no remarkable reduction"; removing IDs raised RStd for llama-2-13B/70B, so the effect is not uniform) [EDIT-REFUTER 18 Oct: "equal accuracy" and "did not help" were overstated, numbers added]; PriDe estimates an ID prior from about 5% permuted samples and divides it out at x1.15 cost: 0-shot MMLU over 20 models RStd -7.6, accuracy +1.2; fine-tuning as a factor was not studied (instruction/chat models were among the 20). https://arxiv.org/html/2309.03882v4 [author-run]. JudgeLM names "swap augmentation" in its abstract as a fine-tuning technique against position bias (https://arxiv.org/abs/2310.17631 [author-run]); that it also swaps the labels is UNVERIFIED (abstract gives no mechanism). PA-GRPO (Mar 2026, RL on verl, LoRA r=32 alpha=64 on all linear layers, 8B): consistency reward across permutations beats swap-style SFT (PIF) on consistency: Llama-3.1-8B MT-Bench Acc/Con/CA 77.6/88.0/71.7 vs PIF 76.1/84.6/70.4; no augmentation-only SFT baseline was run. https://arxiv.org/html/2603.21016v1 [author-run]. Accuracy and order sensitivity can diverge: a flip-rate fall of 20.26% to 12.63% (GPT-4.1 mini, MMLU, two-stage prompting) moved accuracy -0.26 pp, CI [-2.37, 1.75]; an order-invariant-by-construction method (Hidden+Semantic, zero flips) was 35.18 pp worse end to end, but 155 of 1,140 outputs were unscored and counted wrong (conditional accuracy 54.01%), so part of the gap is parse failure. Flip rates across all strategies and four models (GPT-4.1 mini, Claude Haiku 4.5, Qwen2.5-7B, Llama-3.1-8B) ranged 10.96-54.74% on MMLU and 3.75-36.26% on ARC-Challenge. https://arxiv.org/html/2608.11947 [author-run, prompting strategies on hosted/open models; no training]. [EDIT-REFUTER 18 Oct: numbers made exact.]

6. **DPO/SFT for verdict models.** GuardReasoner (full-parameter, Llama 1B/3B/8B, generative reasoning): R-SFT LR 5e-5, 3 epochs, batch 384; HS-DPO LR 5e-6, 2 epochs, beta 0.01, batch 256, with R-SFT loss weight 2; hard = model samples contain both correct and incorrect outputs; HS-DPO (ensemble) added only +0.97 / +0.67 / +0.70 average F1 over R-SFT at 1B/3B/8B. https://arxiv.org/html/2501.18492 [author-run]. Calibration risk of DPO: only secondary assertions (search summaries); UNVERIFIED.

7. **Replay and merging.** No clean replay-ratio sweep exists in what I found. Dong et al. (ACL 2024): with plentiful data the amount of each component matters more than the ratio; sequential training forgets; their dual-stage fix replays a small share of specialised data. https://arxiv.org/abs/2310.05492 [author-run, search summary]. 5% replay at r=4 matched full-FT accuracy in a five-task sequential Llama-3.1-8B LoRA study (single SSRN preprint, one data point, UNVERIFIED). https://papers.ssrn.com/sol3/Delivery.cfm/7343678.pdf?abstractid=7343678 [author-run]. FLOW: upweighting samples the pre-trained model already fits well mitigates forgetting (Gemma-2 2B on MetaMathQA: -0.8% GSM8K, +5.4% retained). https://arxiv.org/abs/2502.02797 [author-run; arXiv page shows submitted 5 Feb 2025, v2 12 Jun 2025; the "ICML 2025" venue is not on that page, UNVERIFIED]. LoRA-delta scaling as WiSE-FT (MemSFT, "Mitigating Alignment Tax with an External Parametric Memory", arXiv 2607.25614, Table 11, Appendix F, VERIFIED by refuter in the arXiv HTML): Qwen3-14B on Biology-Instructions, LoRA update scaled by gamma before merge. Target score / General Avg.: base 6.64 / 83.22; gamma 0.2 8.25 / 83.22; 0.4 19.05 / 83.09; 0.6 27.39 / 82.15; 0.8 31.19 / 77.95. So gamma 0.8 loses 5.27 general points, gamma 0.6 loses 1.07. Single model, single task, a non-guard domain, and the paper's own method beat WiSE-FT. https://arxiv.org/html/2607.25614 [author-run]. [EDIT-REFUTER 18 Oct: numbers confirmed, gamma 0.6 row added; was UNVERIFIED.] Alpha-convention: the PEFT issue (https://github.com/huggingface/peft/issues/1940) shows ONE convention (WiSE-FT: alpha weights the fine-tuned model, alpha=0 base, alpha=1 fine-tuned; implemented as `set_adapter_scale`, closed Aug 2024). It does NOT show that papers disagree; that disagreement claim is UNVERIFIED. The ambiguity that does exist is internal to v2's formula theta(alpha)=init+alpha(base-init), where alpha multiplies (base-init) rather than the fine-tuned delta. Merge-before-forget and ChainLoRA could not be read; no coefficient sweep seen.

8. **Subset tuning limits forgetting (LMM).** Tuning only self-attention projections or MLP gate+up (down frozen) gave strong learning with little forgetting on LLaVA-OV / Qwen2.5-VL 7B; full MLP forgot much more; forgetting correlates (rho 0.84) with a shift in output-token bias. https://arxiv.org/html/2510.08564 [author-run, multimodal, full-parameter, not LoRA].

## 2. Corrections to v2

1. **Missing hyperparameters.** `training_recipe` gives rank 16 only. LR, epochs, warmup, alpha, dropout, target modules are not written. Because C2.1 is a continuation, these matter for forgetting (higher LR means more intruder dimensions and forgetting, source 1). They should be written into the plan or explicitly inherited from C2's recorded values, and the grid sha should include them.
2. **Alpha definition.** `theta(alpha) = init + alpha(base - init)` leaves "init" and "base" ambiguous (which is the C2 start point, which the trained C2.1 model, which the raw Qwen3.5 base?). In the WiSE-FT convention used by PEFT (issue 1940) alpha weights the fine-tuned model, so alpha=1 is the fine-tuned end; in v2's formula alpha=1 lands on "base", so v2 reads reversed from WiSE-FT unless "base" means the trained model. [EDIT-REFUTER 18 Oct: removed the unsupported "papers disagree" claim.] State the endpoint in words in the plan (see "alpha-convention warning"). Also, if "init" is the C2 start, the grid undoes C2's skills as well as the C2.1 delta; a delta-only scale (gamma on the C2.1 LoRA) targets the sequential-LoRA risk named by the intruder-dimension paper more directly.
3. **"20% reversed copies" under-covers token-ID bias.** For 2 options, reversal equals all permutations. For 3+ options, reversal is one of n! orders, and the strongest published finding is that bias attaches to the letter tokens. The reversed copies should be random non-identity permutations (or cyclic rotations) so each content visits each letter.
4. **"Target 1% or less disagreement".** I found no published fine-tuned classifier at that level: prompted models show 11-55% flip rates on MMLU (3.75-36% on ARC-Challenge) in 2608.11947 [EDIT-REFUTER 18 Oct: was "12-54%"]; the best trained judge consistency I found was 88.0% pairwise (PA-GRPO, Llama-3.1-8B MT-Bench; its MCQ consistency metric is different, n_mode/24, and I did not extract it). "Unprecedented" is an absence claim from a limited search and is UNVERIFIED; methods that are order-invariant by construction (zero flips, e.g. Hidden+Semantic in 2608.11947, at a 35 pp accuracy cost there) show 0% is reachable by design, so the 1% target is a statement about the trained model, not about what is possible. The target is not impossible on program-gold rows. Keep it as a reported metric with a CI, not as a claim, and report accuracy beside flip rate.
5. **DPO/ORPO are not in `NOT ADOPTED`.** v2 excludes RL and distillation but is silent on preference optimisation. Add it with the reason in plan change 5.
6. **No label smoothing: reason is fine, support is mixed.** v2's reason (a pilot would need Modal) stands. The literature adds that smoothing helps least for small-hidden-size, large-vocab models and was tested on 1B-8B generative MMLU, not restricted option-letter readouts. v2's choice is defensible; do not describe it as standard practice either way.

## 5. Concrete plan changes (each defended; strength is evidence strength)

1. **Write the LoRA optimisation block into the plan; default from the evidence, conditioned on C2's measured values.** Peak LR no higher than C2's, and if C2 values are unavailable use 1e-4 (cosine, warmup 0.1, range 5e-5 to 2e-4), alpha = 2r = 32, dropout 0.05, all attention and MLP linears present in C2 (same module set for parity), 2 epochs over the 72-90K rows, bf16 LoRA (no QLoRA), LR recorded in the grid sha. Strength: medium for the ranges, weak for the single values; the "no higher than C2's LR" rule rests on the forgetting-vs-LR finding and is my inference for a continuation.
   [EDIT-REFUTER 18 Oct] Added caveats: (a) LR and alpha are coupled. With a fixed LR, LoRA's effective update scales with alpha/r, so if C2 used alpha = r (Unsloth's default is alpha 16 at r 16) then alpha 32 doubles the effective step at the same LR; "LR no higher than C2's" is only meaningful together with "alpha/r no higher than C2's". Record C2's alpha and use the same alpha/r unless a reason is written. (b) The intruder-dimension evidence compares alpha = 2r against alpha = 8, not against alpha = r, so it does not show 2r beats r. (c) The "closest recipe" Nemotron used 5 epochs on a fresh LoRA, with dropout 0.05 and warmup 0.1 from its paper, not from its card. (d) The same intruder paper concludes full fine-tuning beats LoRA at continual learning and "justifies using many different adapters without combining them"; this is evidence against the sequential merge-then-retrain design itself, which the owner already chose, so it strengthens the case for the snapshot stop and the delta-scale arm rather than for any single hyperparameter.
2. **Order-invariance data: random non-identity permutations, not reversal only; keep the KL term conditional; report flip rate with accuracy.** Strength: medium for permutations (token-ID bias), weak for the symmetric-KL term (no classifier-specific evidence; PA-GRPO is RL).
3. **Calibration: keep CE with no label smoothing; fit T on a dev set that includes the hard/near-miss bin; report ECE (state the bin count), Brier and a separate ECE on the trap/near-miss slice.** Reason: guard overconfidence concentrates on adversarial inputs, and ECE can improve through accuracy alone. Strength: medium.
4. **Optional serving-time letter-prior offset (PriDe-style), measured on dev with free L4 reads only; adopt only if it lowers flip rate without lowering accuracy.** Zero added calls: the prior is a constant per-letter offset on the option logits. Strength: weak-medium (tested on pre-fine-tuned models; fine-tuned models untested; would also need a new S1 parity statement because it changes the readout, so keep it out of the default path).
5. **Add DPO/ORPO/preference optimisation to `NOT ADOPTED`.** The only guard-specific measurement I found gave +0.7-1.0 average F1 for a full second stage on generative reasoning outputs, using the model's own sampled outputs; our one-token readout has no sampling diversity, and trap selection on C2's own errors already plays the "hard sample" role. Strength: medium.
6. **Hard-bin criteria: add "unstable under option permutation or small probability margin on C2's reads" to the trap-selection signals.** This is the readout analogue of GuardReasoner's mixed correct/incorrect definition. Strength: weak (my inference; no direct evidence).
