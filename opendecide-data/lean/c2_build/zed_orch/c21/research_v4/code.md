## 0. Headline for the owner (read this first)

1. Very few real code datasets are both clean and useful for our decision families. The clean core is: CodeContests (CC-BY-4.0, human solutions AND human wrong solutions, program-judged tests), Project CodeNet (accept/wrong-answer verdicts from the judge), open-r1 Codeforces submissions (ODC-BY, human code, judge verdicts), APPS train, SWE-Gym (human issues/patches, execution tests), the procedural slice of SWE-smith, ManySStuBs4J and TSSB-3M (CC-BY-4.0, diffs only), LogChunks (CC-BY-4.0, human-labelled CI failure chunks), Juliet (NIST, public domain / CC0) and the DataDog malicious-package dataset (Apache-2.0, human-triaged).
2. The big 2025-2026 SWE-task sets (SWE-rebench V2, SWE-bench-extra, Skywork-SWE, SWE-Dev, SWE-Flow, SWE-Universe, SWE-Stream, R2E-Gym) all put an LLM into the pipeline (install recipes, quality scores, issue rewriting, test or verifier writing). They are OWNER or DENY. The trajectory sets (Open-SWE-Traces, Nemotron-SWE, SWE-Gym trajectories, MALT, HackTrace, Terminal Wrench) are LLM output: DENY.
3. Overlap with our eval targets is the main hidden risk for the clean core. Three concrete overlaps found (all from the cards/papers, no items opened):
   - EquiBench OJ_A / OJ_V / OJ_VA (G13 D27) are built from "a public online-judge dataset" (Puri et al. 2021 = CodeNet is my inference; the search result does not say CodeNet outright) using accepted vs wrong-answer Python submissions (arXiv 2502.12466, f). So CodeNet Python problems may sit inside an eval target. Needs problem-level G13 against the EquiBench pair list.
   - CodeMind v1-v4 used HumanEval, MBPP, CRUXEval, CodeNet and Avatar (arXiv 2402.09664 versions, f). v5 uses HumanEval, CRUXEval, ClassEval, Avatar. So MBPP and CodeNet are possible CodeMind sources (G13 D24).
   - LiveCodeBench takes problems from LeetCode, AtCoder and Codeforces from May 2023 on (HF card, f). Any Codeforces or AtCoder training data dated on or after May 2023 (open-r1 Codeforces problems and submissions, ConDefects, some TACO) needs a date cut-off at 2023-05-01 plus problem-id G13.
4. What this angle cannot give us: the training families T42c, T56g, T57 are Claude-authored generators with execution gold (plan section 2). None of the sets below replaces them. The clean core is best used as P1 realism or transfer slices (as plan v3 T57r does with SWE-Gym and SWE-smith), not as a new P0 source.
5. Gaps found: no public human-labelled "claim vs evidence" (done-claim) set, no human-written reward-hack set with a clear permissive licence, and no human-labelled patch-correctness set with a confirmed permissive licence. Those stay Claude-authored with program gold.
